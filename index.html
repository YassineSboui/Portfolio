Low-Code Platform · NeoLedge

NeoForm

NeoLedge's ECM product needed custom intake forms for every deployment — a developer's project each time. NeoForm turns that into configuration: admins compose forms, tables and referentials, wire runtime behaviour in Blockly, and publish them inside the authenticated Studio or as anonymous public links. On a 2,359-commit team product I led the security and platform work: PostgreSQL row-level security as a second tenant boundary, an AST gate in front of the server-side JavaScript sandbox, and an SSRF filter that runs in the socket connect callback rather than at URL-validation time, closing the DNS-rebinding window.

  • AI co-designer: the model emits typed operations, a deterministic compiler builds the Blockly logic
  • Deny-by-default authorization enforced by a test that walks the live endpoint table
  • Outbound connectors across four SQL engines behind a read-only gate and socket-level SSRF filter

Design System · NeoLedge

NeoLibrary

Every product team at NeoLedge restyled PrimeVue independently, so brand-critical field states drifted. NeoLibrary makes that one tested source of truth: 37 Vue 3 components run PrimeVue 4 unstyled under 27 per-component passthrough configs, where every state-dependent DOM node's classes are computed as pure functions of props and context — an 8-state field spec, seven of them resolved by a six-branch priority chain (disabled > readonly > invalid > warning > focused > default), asserted in unit tests with nothing mounted, including a test that forbids physical padding so RTL stays correct. It also ships NeoBlockly, a visual rule editor with 187 registered block types that compiles a workspace into async JavaScript.

  • 27 Tailwind passthrough configs over PrimeVue 4 unstyled, 8-state spec, 6-branch chain
  • NeoBlockly: 187 block types compiled to async JS, 7 declared toolbox profiles, 6 distinct toolboxes today
  • 585 tests across 58 files, 207 Storybook stories, vue-tsc strict gate in CI
  • RTL direction resolved through 5 ordered sources, enforced by class-level tests

Matching Engine · Personal

Talent Bridge

Keyword ATS filters rank a job title above a candidate who can do the work, and explain neither decision. Talent Bridge parses a PDF CV and scores it against job rows from a SQL Server star-schema warehouse on seven weighted components — skills 0.35, MiniLM embedding similarity 0.25, then role, experience, education, location, opportunity — and the API response carries every sub-score, matched and missing skills, and written reasons. The hard part was false positives: two stages of ceilings cap matches supported only by the job title, so a title hit with a skills sub-score under 35 is held at 62.

  • Two-stage cap layer ceilings title-only and low-signal-skill matches before ranking
  • Missing skills tiered critical to low by demand across 668,704 public postings
  • SSIS star schema, 15 tables, bridge tables decomposing each posting's skill list
  • CNN plus text-evidence CV gate with accept / reject / manual-review verdict

WhatsApp Assistant · Personal

Clinic AI

Turkish clinics sell to foreign patients over WhatsApp, where replies come late and without a price. This answers the Meta webhook in the patient's language and books against an editable weekly calendar. Every price the model writes is re-extracted against an allow-list built from the clinic's price list and FAQ; a reply carrying an unlisted figure is discarded whole, booking marker included. Seven classes of bad booking marker are rejected before an appointment exists, and a coordinator can seize a thread mid-generation — the in-flight reply is dropped at send time. Exercised end to end against a Meta test number: pilot-ready, not yet in production.

  • Price allow-list filter over model output, with Russian, Arabic and Turkish currency words
  • Resident faster-whisper worker transcribes voice notes locally, with a four-level fallback chain
  • Delivery runs inside a per-user promise queue, before the assistant turn is committed
  • 3,118-line operator dashboard: no front-end dependencies, no innerHTML, 8 XSS vectors asserted
